## The documents

### [ARCHITECTURE.md](ARCHITECTURE.md) — how the codebase is organised
The layer map, what each directory is responsible for, the protocol file table,
how a command flows from argument to wire, and the design conventions that are
not obvious from reading the files. **Read this before changing code.**

### [CODE-TRACE.md](CODE-TRACE.md) — every function on the path
A function-by-function trace from `main()` to a byte on the wire and back
through the handler callbacks. 23 sections, 53 function entries each carrying
its `file:line`. Covers the concurrency model, dispatch, each protocol
operation, the file codec, the TFTP shim, the timers, status codes,
customisation points and known defects. **Reference, not a tutorial** — §09 is
shared machinery that §10–§13 build on, so read it first.

### [BUILD.md](BUILD.md) — building, in detail
Every build stage in order, every dependency and how to install it, the Linux
path, the three failure modes that will otherwise stop you, and every linked
resource collected in one place. **§6 is the troubleshooting section.**

### [ARINC615A-CLI-Installation-and-Test-Procedure.docx](ARINC615A-CLI-Installation-and-Test-Procedure.docx) — the engineering document
Step-by-step install for both platforms, command-by-command operation, a
16-case test procedure with expected results and pass/fail criteria, a
troubleshooting matrix, and 13 diagrams. Written to be followed literally.

Generated — do not edit by hand:

```bash
python scripts/generate-user-guide.py     # sources: scripts/generate-user-guide.py + scripts/_diagrams.py
```

### [../README.md](../README.md) — the front door
Overview, the protocol stack and OSI mapping, block and sequence diagrams,
quick start, the full command list, and the two option-parsing quirks.

## Reading order for a new maintainer

1. [../README.md](../README.md) — what it is, and build it once.
2. [ARCHITECTURE.md](ARCHITECTURE.md) — the shape of the code.
3. [CODE-TRACE.md](CODE-TRACE.md) §04–§07 — startup and dispatch, in order.
4. [CODE-TRACE.md](CODE-TRACE.md) §09, then whichever of §10–§13 you need.
5. [../CONTRIBUTING.md](../CONTRIBUTING.md) — the local changes that must
   survive an upstream merge.
