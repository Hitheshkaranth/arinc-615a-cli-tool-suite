# Generator — `ARINC-615A-CLI-Engineering-Trace.docx`

Builds the Word edition of [CODE-TRACE.md](../CODE-TRACE.md). Same 23 sections
and same 53 function entries; the Word edition adds eight block diagrams that
the Markdown does not carry, plus a cover page, a TOC field, a running head and
page numbers.

```bash
python make_doc.py                  # full build, ~10 min (one Chrome run per figure)
python make_doc.py --skip-figures   # rebuild the document from figs/, seconds
```

The document is written to `../ARINC-615A-CLI-Engineering-Trace.docx`.

## Files

| File | Role |
| --- | --- |
| `arinc615a-cli-engineering.html` | Source of record for the prose. Do not edit by hand — it is the published trace export. |
| `block_diagrams.py` | The eight added diagrams, as SVG builders plus the section each is spliced into. |
| `make_doc.py` | Splices the diagrams in, rasterises every figure, calls `build_docx`. |
| `build_docx.py` | Maps the HTML onto Word constructs — headings, function blocks, tables, callouts, code. |
| `figs/` | Rasterised figures, numbered in document order. Regenerated by `make_doc.py`. |

`arinc615a-cli-engineering.html` is never modified. Each run regenerates
`arinc615a-cli-engineering.figured.html` from it, so the build is idempotent and
that file is disposable.

## The added diagrams

Seven figures come from the source export. These eight are additions, drawn from
the source tree and from the ARINC 615A user manual:

| § | Figure | Subject |
| --- | --- | --- |
| 01 | fig1 | Host and target — which side binds which UDP port, and who initiates |
| 05 | fig4 | Dispatch pipeline — `argv` through the command registry to an operation |
| 11 | fig8 | Upload message sequence |
| 12 | fig9 | Media Defined Download message sequence |
| 13 | fig10 | Operator Defined Download — the extra `.LNL`/`.LNA` round trip |
| 14 | fig12 | Protocol file extensions by operation and by writer |
| 16 | fig14 | Nested timer scopes, and the graceful abort chain |
| 20 | fig15 | Link dependencies across applications, libraries and externals |

The `.LCI` / `.LUI` / `.LND` / `.LNO` initialisation file is a host-side TFTP
**read** for every operation — `OperationImpl::initialise` uses
`tftpClientV->readOperation()`. The sequence diagrams and the file matrix show
RRQ accordingly; wording elsewhere that calls it "initiating" a file can read as
a write, and does not mean one.

## Why this is not in `scripts/`

`scripts/generate-user-guide.py` builds the installation and test procedure by
composing content in Python. This generator instead transforms a published HTML
document, so it carries its own source file and figure set and is kept together
with them.

## Requirements

`beautifulsoup4`, `lxml`, `python-docx`, and Google Chrome at the path named in
`make_doc.py`.
